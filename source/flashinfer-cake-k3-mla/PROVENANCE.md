FlashInfer ships Cake-generated FP8 MLA decode kernels for Kimi-K3 (96 heads,
latent 512 + rope 64, 64-token pages) behind
`trtllm_batch_decode_with_kv_cache_mla(backend="cake")`. D runs them over
SGLang's fp8 cache (`gen_stage.py --kv fp8`).

## What is vendored

From `csrc/cake_kimi_k3_mla/` of the FlashInfer checkout, with the local tail-operand repair documented below:

- `cake_kimi_k3_mla_fp8_paged_attention_ea17187e76fd47ab2653_kernel.cu`, the
  `main_wide` program: a two-CTA cluster per (row tile, split) item.

Only this one is vendored, because it is the only program D launches. SGLang
captures its decode graphs planned for the longest context it admits.
FlashInfer's planner (`flashinfer/mla/cake_kimi_k3_mla.py`, `plan_attention`)
at a DCP8 member's 40,960 positions on 152 SMs sends every batch of 1 to 64
rows down the wide route, and every row runs as the same number of splits
(`gen_stage.py` `CAKE_SPLITS`). The binding, the row-tile programs and the
reducers are not needed.

## What is ours

- `build.sh` is the cubin recipe. It uses the flags FlashInfer's JIT gives
  this module (`-O3 -std=c++17 --expt-relaxed-constexpr --use_fast_math`, sm_103a).
- The launch ABI is the binding's, written as manifest data
  (`gen_stage.py` `cake_attn_op`):
  - five 2D `uint8` tensor maps over `[rows][576]`: q, k and v with box
    128 × 64 and the 128 B swizzle, the rope halves with box 64 × 64 and the
    64 B swizzle;
  - block 384, cluster (2, 1, 1), 232,448 B of dynamic shared memory;
  - grid `2 · batch · splits`.

  The binding also asks for the cluster spread scheduling policy and PDL.
  kern sets neither; without PDL the kernel's `griddepcontrol.wait` returns
  at once.
- Cake's reducer is replaced by `source/k3_dcp.cu`'s `CAKE` build. It merges
  the splits' normalized bf16 o and their (max, sum) across the splits and the
  DCP members in one pass.

## Partial-page operand repair

The wide kernel clears only logically invalid K/KR and V rows in shared
memory after their existing TMA completion waits, before the corresponding
MMA. The V clear prevents an unused FP8 NaN row from contaminating valid
output through zero times NaN. The K/KR clear is defense in depth: softmax
already replaces invalid QK score columns with `-CAKE_INF` before taking
the maximum. The tested K/KR clear is retained; a V-only variant has not
been qualified. Global KV bytes and arithmetic on valid operands are unchanged.

This is a local source modification, not a regenerated upstream Cake
artifact. The symbol retains its generated name for ABI compatibility;
the name no longer identifies an unmodified Cake program.

Qualification covers the q1 wide launch used by kern (`m_tiles=1`,
`n_full_items=0`), not general multi-query or row-tile programs. The recorded
component runs contain 37 clean/reference cases, 205 tail-invariance checks
(168 actual poisoned-tail cases and 37 zero-tail controls), and three
changed-metadata graph replays. The bitwise gate compares active partials
against the pristine cubin with zero unused rows. The FP32 reference at
`atol=rtol=0.01` is an additional sanity check, not a quality-equivalence test.
See [the component harness](../../harness/cake_tail/README.md) for commands
and the separate record of earlier scripts and the subsequently executed
public full/empty entry points.

Registry/hash checks, targeted Ruff and clang-format pass; upstream Actions
awaits approval. Ordering: each clear follows CTA0's existing wait on the TMA
phase that both CTAs' copies complete and precedes the two-CTA MMA. PTX ISA
9.0 sections 9.7.9.25.1.2 and 9.7.9.25.2 make a completed phase's copies
available to every participating thread and follow completion with an
implicit generic-async proxy fence; the unmodified kernel already relies on
the same wait before its two-CTA MMA reads the peer CTA's operands. A
`.acquire.cluster` wait at the three clear sites is available if reviewers
prefer an explicit contract; it would change the cubin and be requalified.
The component and supplemental model checks found no ordering failure;
stress is empirical evidence, not a formal memory-model proof. See the
[PTX completion rules](https://docs.nvidia.com/cuda/archive/13.0.0/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-asynchronous-copy-completion-mechanisms-mbarrier)
and [async proxy rules](https://docs.nvidia.com/cuda/archive/13.0.0/parallel-thread-execution/index.html#async-proxy).

An adapted `loop/d/check` comparison also passed on one HGX8 using four
layers, FP8 KV and 640 teacher-forced steps over four rows. Pristine and
repaired FP8 arms preserved one gathered array of 6,553,600 logit values
(four rows × ten retained steps × 163,840 vocabulary), plus 2,560 token IDs
on each of eight ranks. Both arms show the same error against the BF16 TP1
oracle (the standalone 5% maximum-RMS check fails for both), so that
difference comes from the FP8 route, not the repair. This is repair
invariance, not model-quality acceptance. The adaptation
uses local POSIX sharing and identical B300 AR144/DCP128 grids in both
arms. It is neither the author's two-host run nor a qualification of
PR #10's DCP144 geometry. No full-model or serving claim follows.

Across the two recorded hot-cache B300 runs, partial-tail operator overhead
is approximately 2–3 microseconds at B1/B8 and 3.5–5 microseconds at B24,
depending on the run and tail geometry. The second B24 run crossed timing
regimes; neither its marginal-median percentage nor one run's MAD is a
stable overhead estimate. These are operator measurements, not a measured
model-step cost or a serving-throughput claim.

## Re-vendoring

A new upstream source or generated program must re-apply this repair, or
demonstrate that upstream now excludes unused V rows before retiring it.
Rebuild from the chosen source with the recorded toolchain, update the
source/cubin provenance and `kernels.toml` pin together, and rerun the
failing-before smoke, full and empty component modes. Preserve the
zero-tail bitwise control and partial-page poison cases. A source copy or
symbol-name match alone does not establish that the repair survived.
